# SDK audit — A30C–A3B0

Status: `AUDIT_FINDING / MOSTLY_RECONCILED / A338_REVIEW_REQUIRED`

This pass compares the consolidated ABI inventory for A30C–A3B0 against the current BetaWise public SDK surface on branch `sdk/abi-automation`.

## Result

The range is largely already reconciled and does **not** justify another broad umbrella-header expansion.

- A30C–A328 are confirmed null A-line vectors and correctly have no callable public contract.
- A32C is already public as `uint32_t SYS_A32C(void)`.
- A330 is intentionally reached through the BetaWise `getchar()` wrapper rather than exposed as the private raw `_OS3K_getchar` veneer.
- A334 is already public as `int32_t SYS_A334(void)`.
- A33C–A3B0 are the reconstructed C-library surface and are already represented in `os3k/os3k.h`; A350 is intentionally wrapped by public `fputc()` while `_OS3K_fputc` remains private.

Therefore A30C–A3B0 contains no new safe bulk-publication batch analogous to A290–A2AC or the closed subset of A2B0–A308.

## A338 mismatch

A338 is the exception and should be reviewed separately.

The consolidated inventory classifies A338 as:

- `CERRADA_CON_LÍMITE_DE_EVIDENCIA`
- mechanics: closed
- abort-like identity: strong inference
- exact source-level C prototype: not demonstrable from the current corpus

The handler consumes no stack data and does not return normally, while two observed callers physically provide one ignored zero slot. This leaves a historical/source-level calling-shape ambiguity even though the mechanics of the trap are understood.

Current SDK state nevertheless exposes:

```c
void abort(void);
```

and `syscall.c` emits the A338 veneer directly under symbol `abort`.

That declaration should therefore **not** be described as an evidence-A exact recovered vendor prototype. It is at best a compatibility/public convenience surface over a mechanically closed termination trap unless additional source evidence resolves the physical-slot discrepancy.

## Recommended treatment

Do not change A338 source code in this audit-only pass because doing so affects a standard-library public symbol and requires a real m68k build/link gate.

For a future build-validated reconciliation batch, choose deliberately between:

1. retaining `abort(void)` as a documented compatibility surface while explicitly separating it from the recovered raw ABI evidence; or
2. introducing a neutral raw `SYS_A338` veneer and implementing/aliasing `abort(void)` as a wrapper, if that can be done without breaking existing applets or toolchain expectations.

Whichever route is chosen, do not promote A338 from `CERRADA_CON_LÍMITE_DE_EVIDENCIA` merely because the SDK already has an `abort(void)` declaration.

## Build gate

Any A338 source change requires at minimum:

1. `make -C os3k clean all`
2. clean build/link of a representative applet set
3. confirmation that libc/toolchain declarations do not conflict with the chosen `abort` exposure
4. confirmation that the raw A338 physical call shape is preserved

No build validation is claimed by this audit note.
